# Build notes

## Key decisions

- Chose a static React/Vite build rather than a backend service because the competition requires a reliable browser proof of concept with mocked data.
- Designed around a single high-impact 60-second path instead of broad ITR coverage.
- Used fixture-driven synthetic scenarios so judges can replay strong moments without reset.
- Kept calculation helpers separately testable from the UI.
- Used deterministic context-aware explanations instead of a generic chatbot or an LLM tax engine.

## How Codex assisted

Codex helped inspect the supplied brief and reference, research public product and official sources, scaffold the interface and documentation, and add calculation tests. Product positioning, scope, and all future submission claims should be reviewed and owned by the entrant before submission.
